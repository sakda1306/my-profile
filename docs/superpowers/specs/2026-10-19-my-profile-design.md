## 1. เว็บนี้คืออะไร และทำไปทำไม

เว็บโปรไฟล์ส่วนตัวของโปรแกรมเมอร์คนหนึ่ง ทุกคนเปิดดูได้โดยไม่ต้องล็อกอิน เจ้าของคนเดียวล็อกอินเข้าหน้าแอดมินแล้วแก้ไขได้ทุกอย่างผ่านหน้าเว็บ ไม่ต้องแก้โค้ดหรือ deploy ใหม่ เช่น เปลี่ยนรูป เพิ่มหรือแก้ความสามารถ เพิ่มใบประกาศ เพิ่มโปรเจกต์ สร้างหมวดใหม่ และเขียนบทความ

จุดเริ่มต้นของเนื้อหามาจาก GitHub ของเจ้าของ คือ repo ภาษาที่ใช้ และ profile README หลังจากใส่ข้อมูลตั้งต้นแล้ว เจ้าของจะดูแลเนื้อหาเองทั้งหมดในหน้าแอดมิน

เงื่อนไขสำคัญคือ**ต้องไม่มีค่าใช้จ่าย** ใช้เฉพาะแพลนฟรีของ Vercel และ Supabase

## 2. เป้าหมาย สิ่งที่ไม่ทำ และสิ่งที่ห้ามเกิด

### เป้าหมาย
- หน้าสาธารณะสองภาษา ไทยและอังกฤษ มีปุ่มสลับภาษา
- หน้าแอดมิน (`/admin`) ที่แก้ไขเนื้อหาได้ทุกส่วน ทั้งข้อความ รูป ไฟล์ ลำดับ และการซ่อนหรือแสดง
- หมวดตั้งต้นสี่หมวด คือโปรไฟล์ ความสามารถ โปรเจกต์ และใบประกาศ บวกกับหมวดที่เจ้าของสร้างเองได้จากแม่แบบ
- บล็อกบทความ มี editor แบบ Notion และเก็บเป็นร่างได้
- ปุ่มแปลอัตโนมัติ TH ↔ EN ในหน้าแอดมิน
- deploy ฟรีบน Vercel โดยใช้ Supabase เป็นฐานข้อมูล ระบบล็อกอิน และที่เก็บไฟล์
- หน้าสาธารณะโหลดเร็ว และ SEO ดีทั้งสองภาษา

### สิ่งที่ไม่ทำ
- ไม่มีผู้ใช้หลายคน: มีแอดมินคนเดียว ปิดการสมัครสมาชิก
- ไม่มีคอมเมนต์ ไม่มีระบบสมาชิกสำหรับคนดู
- ไม่มีฟอร์มติดต่อที่ส่งอีเมล ใช้ลิงก์ติดต่อแทน (ผมเลือกเอง เพราะการส่งอีเมลต้องใช้บริการเพิ่ม)
- ไม่ sync กับ GitHub อัตโนมัติ: ข้อมูลจาก GitHub ใส่ครั้งเดียวตอนเริ่ม
- ไม่มี page builder แบบลากวางอิสระทุกพิกเซล ใช้แม่แบบหมวดแทน (ดูข้อ 5.2)
- ไม่มี backend แยก เช่น FastAPI (เจ้าของตัดสินใจแล้ว)

### สิ่งที่ห้ามเกิด
- **หน้าตาไม่ตรงกับ reference ดีไซน์ของเจ้าของ** ข้อนี้สำคัญที่สุด จึงห้ามล็อกหน้าตาของหน้าสาธารณะก่อนได้เห็น reference (ดูข้อ 9)
- คนอื่นที่ไม่ใช่เจ้าของแก้ข้อมูลได้
- API key หรือ secret หลุดไปอยู่ใน repo หรือส่งไปถึงเบราว์เซอร์
- การเพิ่มหรือแก้เนื้อหาต้องไปแก้โค้ด
- เกิดค่าใช้จ่าย

## 4. โครงสร้างระบบ

```
คนดู ──► Vercel (Next.js, หน้าสำเร็จรูป/ISR) ──อ่าน──► Supabase Postgres
                                                     Supabase Storage (รูป, PDF)
เจ้าของ ──► /admin (Next.js server actions) ──เขียน──► Supabase (ผ่าน RLS)
                       └── ปุ่มแปล ──► Gemini API (ฝั่ง server เท่านั้น)
Vercel Cron (วันละครั้ง) ──► /api/keepalive ──► query Supabase เบาๆ
```

ผมเลือกสิ่งต่อไปนี้เอง ผู้สร้างเปลี่ยนได้ถ้ามีเหตุผลดีกว่า:
- **Next.js (App Router) + TypeScript**
- **Tailwind CSS** กำหนดค่าหน้าตาทั้งหมดผ่าน design tokens (CSS variables) ที่เดียว
- **Supabase JS** ร่วมกับ `@supabase/ssr` สำหรับ session ใน server components และ server actions
- **next-intl** จัดการสองภาษา ใช้ path แยก `/th/...` และ `/en/...`
- **Tiptap** เป็น editor บทความ เก็บข้อมูลเป็น JSON
- **dnd-kit** สำหรับลากจัดลำดับในหน้าแอดมิน
- **zod** ตรวจข้อมูลทุกฟอร์มฝั่ง server

### การโหลดหน้าและอัปเดตเนื้อหา
- หน้าสาธารณะสร้างแบบ static/ISR คนดูแทบไม่ได้ยิง query ไปที่ Supabase
- พอแอดมินบันทึก server action จะเรียก `revalidatePath` หรือ `revalidateTag` เฉพาะหน้าที่เกี่ยวข้อง ทั้งสองภาษา ให้เห็นผลทันที
- หน้าแอดมินเป็น dynamic อ่านข้อมูลสดเสมอ

### กัน Supabase หลับ
Supabase แพลนฟรีจะหยุดโปรเจกต์ชั่วคราวถ้าไม่มีการใช้งาน 7 วัน วิธีกันคือตั้ง Vercel Cron วันละครั้ง ให้เรียก `/api/keepalive` ที่ query ตารางเล็กๆ หนึ่งครั้ง ป้องกันด้วย `CRON_SECRET`

## 5. เนื้อหาและฐานข้อมูล

### 5.1 หลักการ
- ข้อความที่แสดงต่อคนดูมีสองคอลัมน์ `*_th` และ `*_en` ส่วนชื่อเฉพาะ เช่นชื่อภาษาโปรแกรมหรือชื่อผู้ออกใบประกาศ เก็บคอลัมน์เดียว
- **กฎแสดงภาษา:** ถ้าภาษาที่ขอว่าง ให้แสดงอีกภาษาแทน ไม่แสดงช่องว่าง
- ทุกตารางที่เป็นรายการมี `sort_order int`, `is_visible bool`, `created_at` และ `updated_at`
- รูปและไฟล์เก็บใน Supabase Storage ในตารางเก็บแค่ path

### 5.2 หมวด (sections) ของหน้าแรก
หน้าแรกประกอบจากรายการในตาราง `sections` เรียงตาม `sort_order` แต่ละหมวดมี `type` ที่บอกว่าใช้แม่แบบไหน:

| type | ข้อมูลมาจาก | หมายเหตุ |
|---|---|---|
| `hero` | `profile` | ชื่อ รูป คำแนะนำตัว ปุ่ม resume หรือติดต่อ หมวดตั้งต้นที่ลบไม่ได้ |
| `skills` | `skills` | หมวดตั้งต้น ลบไม่ได้ แต่ซ่อนได้ |
| `projects` | `projects` | หมวดตั้งต้น ลบไม่ได้ แต่ซ่อนได้ |
| `certificates` | `certificates` | หมวดตั้งต้น ลบไม่ได้ แต่ซ่อนได้ |
| `latest_posts` | `posts` | บทความล่าสุด N เรื่อง หมวดตั้งต้น |
| `contact` | `profile.links` | หมวดตั้งต้น |
| `rich_text` | `sections.body_*` | สร้างเองได้: ข้อความยาวแบบ Tiptap |
| `gallery` | `section_items` | สร้างเองได้: รูปหลายรูปพร้อมคำบรรยาย |
| `cards` | `section_items` | สร้างเองได้: การ์ดที่มีรูป หัวข้อ คำอธิบาย และลิงก์ |
| `timeline` | `section_items` | สร้างเองได้: รายการที่มีช่วงวันที่ เช่น การศึกษา หรือการแข่งขัน |

เจ้าของสร้าง ลบ เปลี่ยนชื่อ ลากเรียง และซ่อนหมวดแบบสร้างเองได้ ส่วนหมวดตั้งต้นทำได้ทุกอย่างยกเว้นลบ

### 5.3 ตาราง

- **`profile`** (แถวเดียว): `full_name_th/en`, `headline_th/en`, `bio_th/en` (Tiptap JSON), `university_th/en`, `avatar_path`, `resume_path_th/en` (PDF ไม่บังคับทั้งคู่ ถ้ามีไฟล์เดียวให้ใช้ไฟล์นั้นทั้งสองภาษา ตามกฎข้อ 5.1 ผมเลือกเอง), `email`, `location_th/en`, `links jsonb` (เก็บเป็นรายการ `{label, url, icon}` เช่น GitHub, LinkedIn, Facebook) และ `github_username`
- **`sections`**: `id`, `type`, `slug` (ใช้เป็น anchor), `title_th/en`, `subtitle_th/en`, `body_th/en` (สำหรับ `rich_text`), `settings jsonb` (เช่นจำนวนคอลัมน์ จำนวนบทความ), `is_system bool`, `sort_order`, `is_visible`
- **`section_items`**: `id`, `section_id`, `title_th/en`, `body_th/en`, `image_path`, `link_url`, `start_date`, `end_date`, `sort_order`, `is_visible`
- **`skills`**: `id`, `name`, `category` (`language`, `framework`, `tool`, `ai_data`, `soft`), `icon` (ใช้ชื่อไอคอนจากชุด skillicons หรือ simple-icons หรืออัปโหลดรูปเอง), `note_th/en` (คำอธิบายสั้น ไม่บังคับ), `sort_order`, `is_visible`
- **`projects`**: `id`, `slug`, `title_th/en`, `summary_th/en`, `my_role_th/en`, `body_th/en` (Tiptap JSON ไม่บังคับ ใช้ในหน้ารายละเอียด), `stack text[]`, `repo_url`, `demo_url`, `cover_path`, `is_featured`, `start_date`, `end_date`, `sort_order`, `is_visible`
- **`project_images`**: `id`, `project_id`, `path`, `caption_th/en`, `sort_order`
- **`certificates`**: `id`, `title_th/en`, `issuer`, `issued_on`, `expires_on`, `image_path`, `file_path` (PDF ไม่บังคับ), `credential_url`, `sort_order`, `is_visible`
- **`posts`**: `id`, `slug`, `title_th/en`, `excerpt_th/en`, `content_th/en` (Tiptap JSON), `cover_path`, `tags text[]`, `status` (`draft` หรือ `published`), `published_at`, `updated_at`
- **`admins`**: `user_id` (อ้างอิง `auth.users`) เป็นรายชื่อผู้มีสิทธิ์เขียน มีแถวเดียวคือเจ้าของ

ใช้ migration ของ Supabase CLI (`supabase/migrations/*.sql`) ให้สร้างฐานข้อมูลซ้ำได้จาก repo

### 5.4 สิทธิ์ (RLS)
- เปิด RLS ทุกตาราง
- `select`: คนทั่วไป (`anon`) อ่านได้เฉพาะแถว `is_visible = true` ส่วน `posts` อ่านได้เฉพาะ `status = 'published'` แอดมินอ่านได้ทุกแถว
- `insert`, `update`, `delete`: ทำได้เฉพาะเมื่อ `auth.uid()` อยู่ในตาราง `admins` ตรวจผ่านฟังก์ชัน `is_admin()`
- Storage: bucket `media` เป็น public read ส่วนการเขียนและลบทำได้เฉพาะแอดมิน
- `SUPABASE_SERVICE_ROLE_KEY` **ห้ามใช้ในโค้ดของแอป** ใช้เฉพาะสคริปต์ seed ที่รันในเครื่อง
- ต้องมีการทดสอบยืนยันว่า `anon` เขียนไม่ได้ และเห็นแถวที่ซ่อนหรือร่างไม่ได้

## 6. หน้าเว็บ

### สาธารณะ (ทุกหน้ามีทั้ง `/th` และ `/en`)
- `/` (หน้าแรก): หมวดทั้งหมดเรียงตาม `sections`
- `/projects/[slug]`: รายละเอียดโปรเจกต์ รูปหลายรูป เนื้อหาเต็ม และลิงก์
- `/blog` และ `/blog/[slug]`: หน้ารวมบทความ (กรองตามแท็กได้) และหน้าบทความ ส่วนบล็อกโค้ดใช้ syntax highlighting
- ปุ่มสลับภาษาอยู่ที่แถบเมนู จะพาไปหน้าเดียวกันในอีกภาษา
- ภาษาตั้งต้นตอนเข้าครั้งแรกเลือกตาม `Accept-Language` แล้วจำค่าที่เลือกไว้ใน cookie
- SEO: metadata และ Open Graph แยกภาษา, `hreflang`, `sitemap.xml` และ `robots.txt`
- **SEO ตอนแสดงภาษาสำรอง (ผมเลือกเอง):** ถ้าหน้าในภาษาที่ขอไม่มีเนื้อหาหลักของตัวเอง แล้วต้องแสดงอีกภาษาแทน ให้ตั้ง canonical ไปที่หน้าภาษาที่มีเนื้อหาจริง ไม่ใส่ใน `sitemap.xml` และ `hreflang` ของภาษานั้น และแสดงป้ายเล็กๆ ว่า "Available in Thai only" หรือ "มีเฉพาะภาษาอังกฤษ" ส่วนบทความยังแสดงในหน้ารวมบทความของทั้งสองภาษา พร้อมป้ายเดียวกัน

### แอดมิน (`/admin` ภาษาไทยภาษาเดียว และไม่ให้ search engine เก็บ)
- `/admin/login`: ล็อกอินด้วยอีเมลกับรหัสผ่านผ่าน Supabase Auth และปิดการสมัครใหม่ในการตั้งค่า Supabase
- หน้าแดชบอร์ด: ทางลัดไปแต่ละส่วน และลิงก์เปิดดูหน้าเว็บจริง
- จัดการโปรไฟล์ หมวด (สร้าง ลบ เรียง ซ่อน) ความสามารถ โปรเจกต์ (รวมรูปหลายรูป) ใบประกาศ รายการในหมวดที่สร้างเอง และบทความ
- ทุกรายการลากเรียงได้ มีสวิตช์ซ่อนหรือแสดง และต้องยืนยันก่อนลบ
- ตอนลบรายการ ให้ลบไฟล์ที่ผูกอยู่ใน Storage ด้วย
- ช่องข้อความสองภาษาวางคู่กันเป็น TH และ EN แต่ละคู่มีปุ่มแปล (ข้อ 7)
- อัปโหลดรูป: ย่อในเบราว์เซอร์ก่อนส่ง เป็น WebP ด้านยาวไม่เกิน 1600px ส่วน PDF จำกัดไฟล์ละ 10 MB
- ล็อกอินค้างได้นาน เพราะมีผู้ใช้คนเดียว (ผู้สร้างกำหนดระยะเวลาเอง)
- **ดูตัวอย่างก่อนเผยแพร่ (ผมเลือกเอง):** บทความร่าง รายการที่ซ่อน และหน้าแรกทั้งหน้า มีปุ่ม "ดูตัวอย่าง" ที่เปิดหน้าสาธารณะจริงในโหมดตัวอย่าง ใช้ Next.js `draftMode` เปิดได้เฉพาะแอดมินที่ล็อกอินอยู่ โหมดนี้อ่านข้อมูลสดโดยไม่ผ่าน cache และมีแถบบอกว่ากำลังอยู่ในโหมดตัวอย่าง

## 7. ปุ่มแปลอัตโนมัติ

- อยู่ข้างช่องข้อความสองภาษาทุกคู่ มีปุ่ม "TH → EN" และ "EN → TH"
- เรียก server action ที่ตรวจก่อนว่าผู้เรียกเป็นแอดมิน แล้วจึงเรียก Gemini API ด้วย `GEMINI_API_KEY` คีย์ต้องไม่ถึงเบราว์เซอร์เด็ดขาด
- ชื่อโมเดลอ่านจาก `GEMINI_MODEL` ค่าตั้งต้นเป็นรุ่น Flash ที่ใช้ฟรีได้ในช่วงที่สร้าง
- ผลแปลเติมลงช่องปลายทางให้เจ้าของตรวจ **ไม่บันทึกเองอัตโนมัติ**

## 11. การตั้งค่าและ secret

- `.env.local` ห้าม commit ส่วน `.env.example` ให้ commit โดยมีแค่ชื่อตัวแปร
- ตัวแปร: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` (ใช้เฉพาะ seed ในเครื่อง), `GEMINI_API_KEY`, `GEMINI_MODEL`, `CRON_SECRET` และ `NEXT_PUBLIC_SITE_URL`
- **เจ้าของต้องทำเอง:** สมัคร Supabase และ Vercel, สร้างโปรเจกต์, สร้างบัญชีแอดมินใน Supabase Auth, เอา Gemini API key และใส่ env ใน Vercel ส่วนผู้สร้างเขียนขั้นตอนไว้ใน README
- โดเมน: ใช้ `*.vercel.app` ไปก่อน
- กฎ git ของเจ้าของ: ห้ามมีชื่อหรือข้อความอ้างถึงผู้ช่วยเขียนโค้ดใน commit และไฟล์ใดๆ, โฟลเดอร์ตั้งค่าเครื่องมือส่วนตัวในเครื่องต้องไม่เข้า git (กันไว้ใน `.git/info/exclude`), และต้องถามเจ้าของก่อน commit หรือ push ทุกครั้ง
